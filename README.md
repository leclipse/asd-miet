# Лабораторная №1 на основе шаблона преподавателя

Весь C++ находится в `src/main.cpp`. Заголовочные файлы не нужны.
Сохранены типы Vector, SortFunction, SearchFunction, Order, генераторы,
эталонные Std-функции и структура TestSort/TestSearch исходного шаблона.
Комментарии исправлены на UTF-8.

## Что добавлено

- InsertionSort и SelectionSort — две сортировки со средним временем Θ(n²).
- MergeSort — сортировка слиянием, Θ(n log n).
- LinearSearch и BinarySearch — собственные поиски, возвращающие индекс или -1.
- Проверки правильности, включая пустые массивы, дубли и границы int.
- CSV с каждым повтором, средним временем и выборочным стандартным отклонением.
- Необязательный plot.py для построения графиков.

StdSort/StdLinearSearch/StdBinarySearch оставлены как эталоны преподавателя
исключительно для проверки результатов вне измеряемых интервалов. Собственные
алгоритмы не вызывают std::sort, std::find, std::lower_bound или std::merge.

## Исправления методики шаблона

1. Перед каждой сортировкой восстанавливается исходный массив. Иначе убывающий
   массив после первого повтора становится возрастающим.
2. Используется монотонный steady_clock, время хранится как дробное число мс:
   короткие операции не округляются до нуля целых миллисекунд.
3. Для каждого повтора накапливается не менее 100 мс измеренного времени,
   затем оно делится на число операций. Таких повторов 10.
4. Результаты поиска накапливаются в контрольной сумме; вызов идёт через volatile
   указатель на функцию. Это сохраняет реальные поисковые вызовы при оптимизации.
   Измерение включает небольшие расходы косвенного вызова, цикла и суммы.
5. Вместо rand() % (...) применён uniform_int_distribution и фиксированный seed.
   Выражение RAND_MAX + 1 исходного генератора могло переполнить int на некоторых
   платформах. Новый генератор также не имеет смещения от взятия по модулю.
6. Проверки не зависят от assert, который может отключаться в release-сборке.

## Сборка и запуск

Из корня проекта с установленными Meson, Ninja и компилятором C++:

```sh
meson setup build --buildtype=release
meson compile -C build
meson test -C build --print-errorlogs
```

Если build уже существует, вместо setup: `meson configure build -Dbuildtype=release`.

Windows PowerShell:

```powershell
.\build\asd-lab.exe --check
.\build\asd-lab.exe --quick
.\build\asd-lab.exe
```

Linux: `./build/asd-lab` с теми же аргументами.

Без Meson (GCC/MinGW):

```sh
g++ -std=c++17 -O2 -Wall -Wextra -Wpedantic src/main.cpp -o asd-lab
```

На Windows запускайте полученный `asd-lab.exe`. Сохраняйте исходник в UTF-8.

- `--check`: только проверка правильности.
- `--quick`: короткая проверка всего процесса (2 повтора по >=1 мс, n=250,500,1000).
  Это НЕ окончательные измерения для отчёта.
- Без аргументов: полный опыт (10 повторов по >=100 мс). Он занимает несколько
  минут или больше. Во время опыта виден прогресс по завершённым сериям.

## Размеры и условия

Размеры удваиваются от 250. Пределы в main не включаются:

| Алгоритмы | Предел | Последний размер |
|---|---:|---:|
| Вставки, выбор | 10 000 | 8 000 |
| Слияние | 3 000 000 | 2 048 000 |
| Линейный поиск | 10 000 | 8 000 |
| Бинарный поиск | 1 000 000 | 512 000 |

Пределы можно менять в main. «До 10 миллионов» в задании приведено как пример,
а не обязательный размер для каждого алгоритма. Полный перебор всех запросов
линейного поиска требует Θ(n²) времени, поэтому для него предел существенно ниже.

Сортировки измеряются на возрастающем, убывающем и случайном входе.
Случайный вход содержит числа от 0 до 1 000 000 с возможными повторениями.
При одном n алгоритмы получают один и тот же случайный массив. В рамках серии
этот массив повторяется: стандартное отклонение отражает разброс времени, а не
разброс по разным случайным массивам. Для более широкой выборки можно изменить
seed в TestSort и повторить запуск, предварительно сохранив предыдущие CSV.

Копирование входа, создание эталона и проверка правильности не входят в время
сортировки. Выделение буфера MergeSort входит. Память прогрета копированием и
повторными вызовами; это не измерение холодного доступа к памяти. На маленьких n
существенны накладные расходы таймера, поэтому выводы делаются по большим n.

Для успешного поиска один пакет — последовательный поиск каждого значения
массива ровно один раз. Получается точное среднее по позициям для этого массива.
Для неуспешного поиска каждый запрос ищет -1000; линейный поиск просматривает весь
массив. Пакет повторяется до минимальной длительности. Время в CSV относится
к ОДНОМУ запросу, а не всему пакету. Обоим поискам требуется отсортированный вход
в эксперименте; BinarySearch дополнительно требует его по контракту функции.

## Таблицы и графики

В рабочем каталоге создаются `raw.csv` и `summary.csv` (перезаписываются).
Короткий режим создаёт отдельные `quick-raw.csv` и `quick-summary.csv`.
Поля summary: kind, algorithm, case, n, repeats, mean_ms, stddev_ms.
mean_ms — среднее время одной операции; stddev_ms — выборочное стандартное
отклонение между повторами, не готовый доверительный интервал.
CSV: запятая-разделитель, точка в дробях. Импортируйте в Excel через меню «Данные».

Автоматически построить пять PNG (Python с matplotlib):

```sh
python -m pip install matplotlib
python plot.py summary.csv
```

Графики: три случая сортировок и два случая поиска. Обе оси логарифмические.
Для тестовых CSV: `python plot.py quick-summary.csv`.
Для отчёта запишите процессор, ОС, версию компилятора и флаги сборки.

## Теория

| Алгоритм | Лучший | Средний | Худший | Дополнительная память |
|---|---|---|---|---|
| InsertionSort | Θ(n) | Θ(n²) | Θ(n²) | Θ(1) |
| SelectionSort | Θ(n²) | Θ(n²) | Θ(n²) | Θ(1) |
| MergeSort | Θ(n log n) | Θ(n log n) | Θ(n log n) | Θ(n) |
| LinearSearch | Θ(1) | Θ(n) | Θ(n) | Θ(1) |
| BinarySearch (эта реализация) | Θ(log n) | Θ(log n) | Θ(log n) | Θ(1) |

BinarySearch здесь находит первое вхождение: даже при равенстве среднего элемента
он продолжает сужать диапазон, поэтому у этой реализации лучший случай тоже
Θ(log n) для непустых растущих массивов. Вариант с немедленным возвратом при
равенстве имел бы лучший случай Θ(1), но мог бы вернуть не первый дубль.

Для вставок возрастающий вход — лучший случай, убывающий — худший. Выбор делает
n(n-1)/2 сравнений независимо от порядка. Слияние не пропускает упорядоченные
подмассивы: порядок времени одинаков во всех случаях. Для поиска средний случай
означает равновероятность успешного запроса к любой позиции.

Для сопоставления с теорией можно проверить, становятся ли примерно постоянными
T(n)/n, T(n)/n², T(n)/(n log₂ n), T(n)/log₂ n для соответствующих алгоритмов.
Итоговые экспериментальные выводы и PDF — после проверки кода и полного запуска.
